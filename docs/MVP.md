# 产品范围与后续演进

## 用户目标

学会掌柜智库的模块职责、请求路径、函数关系和 State 流转。每次学习能从问题出发，找到关系，再核对代码。

主要学习循环：选学习路径 → 定位节点 → 看上下游 → 点关系 → 核对证据 → 标记已学会。

## 第一版范围

| 学习问题 | 产品能力 | 验收依据 |
| --- | --- | --- |
| 项目由什么组成？ | 项目/模块总览；展开模块与文件 | 能从智能问答模块进入 query_service.py 再进入 query 函数 |
| 一个问题经过什么？ | LangGraph 显式流程图、条件候选 | 问答图显示四路检索与答案提前输出的候选分支 |
| 谁依赖谁？ | imports 与保守调用候选；跨文件关联图 | sse_generator 的关联图能看到 stream、队列与打包函数 |
| 数据怎样传？ | State 字段与同名字段候选线 | 选择 State 数据流能看到 pending 标记和局限说明 |
| 如何知道图没编造？ | 代码路径、符号、行号、哈希 | 点击 main_graph.py 连线可定位 add_edge 原文 |
| 怎么开始学习？ | 4 条路线、12 个术语、本地进度 | 路径每一步能跳到源码节点，进度刷新后保留 |

## 技术与隔离

- 独立目录，没有修改业务仓库。
- 本地服务采用 Python 标准库；不用掌柜智库的重型模型依赖。
- 数据层是 JSON；前端是 HTML/CSS/JS 与本地固定版本的 G6 Canvas 发行包，无需 CDN。
- 扫描器只解析文本，不 import app，不运行图，不连接数据库。
- 附带源码学习快照，支持 `--repo` 指向实际开发目录。

## 有意保留的限制

静态图不是运行记录。通配符导入、实例方法、别名重绑定及动态路由不做完整求解。State 关系是文件级字段交集，无法证明时序、真实返回与某次请求的路径。节点排布可临时拖动，不持久化；学习进度保存在浏览器。关系不会由用户点击一次就自动晋级为“已验证”。

当前是桌面优先的学习工具，窄屏会把详情放到画布下方；密集图需要缩放、筛选或搜索。大型仓库的全局展示和增量索引暂未作为目标。

## 推荐后续顺序

1. 精读问答主线，人工补充 query、商品确认、答案输出的输入/输出解释，并附代码锚点。
2. 针对真实痛点完善静态解析：相对导入、通配符来源提示、符号作用域；仍保持推断待验证。
3. 建立人工审核覆盖层，保存审阅人、提交、证据和失效规则，避免重新扫描抹掉审阅结论。
4. 单独设计运行时采样。先征求用户允许再改业务代码；从一条脱敏请求验证真实链路，运行记录与源码配置分开展示。
5. 有稳定证据后再加入基于项目源码的 AI 学习问答。需要 API 配置、隐私边界和逐条证据引用，不能以模型回答替代源码确认。
