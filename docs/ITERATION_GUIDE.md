# 如何继续与 Codex 迭代

## 每次给一个可以验收的目标

使用“遇到的问题 → 希望看到的效果 → 怎么算完成”描述需求，比只说“再优化一下”更有效。

例如：

> 我看不懂问答的四路检索。请增加“分步学习模式”：从 /query 入口开始，点击下一步依次查看商品确认、检索、融合、重排和答案输出。每一步展示通俗说明、输入/输出 State 字段、真实代码证据。可能的分支要标注待验证，不能把教学动画称为真实执行。完成后实际启动并验证。

也可以只改一个小问题：

> node_rerank 的说明太像源码注释。请核对真实实现，为它补充中文职责、输入、输出和一个小例子；标明哪些解释是推断，并保留代码定位。

## 迭代过程

1. 先核对当前文件、源码目录和版本，明确需要改的行为。
2. 完成独立学习网站的修改，保留已有功能与证据规则。
3. 实际验证受影响的功能、启动入口和页面；交付可运行文件与验收结果。
4. 你试用后，用截图或一个具体例子反馈哪里不懂、哪里不顺。

不要求每次换框架或大改架构。优先改善学习效果。

## 建议顺序

1. **补讲解**：给常用节点补“职责、输入、输出、例子、常见误区”。
2. **分步学习**：围绕问答和导入两条主线增加教学步骤，避免同时展示过多关系。
3. **学习记录**：补节点笔记、复习清单，以及学习进度的导出和导入。
4. **提高解析准确度**：补相对导入、作用域和人工审核层，优先减少误导。
5. **运行时与 AI**：在证据充分后单独规划；需要业务改动、外部服务或 API 时先确认边界。

## 新聊天的交接

把本产品目录位置和 docs/CODEX_PROMPT.md 的内容一起提供，并写明本轮只做哪一项改进。不要只提供网站截图；真实源码、学习数据和验收记录有助于延续工作。

更新掌柜智库业务代码后，告诉 Codex 日常开发仓库的完整路径，并重新扫描。GitHub 链接用来确定来源；本地路径用来保证图谱对应你正在学习的版本。

## 始终保留的约束

- 学习网站与业务代码独立，未经确认不修改业务、不推送 GitHub。
- 自动推断关系必须待验证；代码事实必须附路径、行号/符号。
- 不能将教学动画称为实际请求的运行记录。
- 不能只验证 Python 入口；Windows 启动脚本修改后要真实通过 cmd.exe 测试。
- 每次交付说明改了什么、验证了什么、尚有什么限制。
